The rule

PostorderLeft → Right → Root
Postorder records a node on the way back up, once both children are completely done. The root is always last. Every bottom-up problem in this course — height, diameter, balanced, maximum path sum — is postorder with something more interesting than push_back in that final position.
On the pencil walk, postorder is the last touch of a node — you are leaving it for good and going back to its parent.

Step

Call stack

The stack grows downwards on screen and the highlighted frame at the bottom is the one running. Everything above it is paused. The deepest the stack ever gets is the height of the tree — that is the O(H) in the space complexity.

This is the shape of every bottom-up algorithm

      
Replace push_back with a calculation and you have height, diameter, balance, and maximum path sum — all of them postorder:
int solve(TreeNode* r) {    if (!r) return /* empty answer */;    int L = solve(r->left);   // LEFT    int R = solve(r->right);  // RIGHT    return combine(L, R, r->val);  // ROOT}
A node can only combine what its children report, so it must run after them. That is postorder, and it is why parts 5 to 8 of the course all look the same.

    

    

      
Complexity

      
TimeO(N)
SpaceO(H)
Every node is entered once and left once, so the time is O(N) for N nodes. The extra space is the call stack, which is as deep as the tree is tall: H is the height. A balanced tree gives O(log N); a skewed tree gives O(N) and can genuinely overflow the stack. Load the Skewed preset and watch the stack panel to see why.
