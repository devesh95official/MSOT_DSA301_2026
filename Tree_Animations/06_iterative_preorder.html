Why the right child is pushed first

A stack hands things back in the reverse order you put them in. Preorder must process left before right, so the left child has to be the one on top — which means it must be pushed last. Push right, then left.
Swap those two lines and you get Root Right Left, which is a real traversal (it is the first half of the two-stack postorder trick) but it is not preorder. Try it on paper before you trust it.
What was the recursive call stack actually storing? Only two things: which node we were in, and how far through the body we had got. Preorder is the easy case to convert because a node is finished with the moment it is processed — nothing has to be remembered about it afterwards. That is why inorder and postorder are harder.

Complexity

      
TimeO(N)
SpaceO(H) auxiliary
Each node is pushed once and popped once: O(N) time. The stack holds at most one node per level along the current path, so its size is bounded by the height H — O(log N) for a balanced tree, O(N) for a skewed one. The output vector is O(N), but that is the answer, not auxiliary space. Compared with recursion, the asymptotic space is the same; what you gain is that you control it, so a 105-deep tree cannot blow the program's call stack.
