What “balanced” means here

A binary tree is height-balanced when, at every node, the heights of the left and right subtrees differ by at most 1. Not just at the root — at every single node. That is why the check has to be a recursion and not one comparison.
The sentinel trick. We want two things back from each subtree: “are you balanced?” and “how tall are you?”. Rather than returning a pair, we return the height, and reserve the impossible value −1 to mean “somebody below me is unbalanced”. One int carries both facts, and the early return -1 lines stop the work as soon as the answer is settled.
The same pattern appears whenever a subtree must report two things: return a struct, or encode a failure in a value the answer can never legitimately take.

Where the naive version goes wrong is not the comparison — it is that height() is a second traversal started inside a traversal. Each node ends up walked once per ancestor, so the total is O(N×H): O(N log N) if the tree happens to be balanced, and a full O(N²) when it is skewed. Load the Skewed preset and compare the two numbers.
The general rule: if you are calling a function that walks a subtree from inside a recursion that already walks that subtree, you are doing the work twice. Make the recursion return what the outer call wanted to recompute.
