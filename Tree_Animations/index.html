Binary Trees & Tree Algorithms

Sixteen self-contained visualizers. Every one is a single HTML file — open it in any browser, no server and no internet needed. Each algorithm is a list of precomputed steps, so you can step forwards and backwards through it, pause anywhere, and read a plain-English explanation of why that step happened, with the matching C++ line highlighted.

Pages 10 to 12 are the ones worth slowing down on. Ask the class for the brute force first, let them find the repeated work themselves, then show the rewrite — the counters on pages 11 and 12 exist for exactly that moment.

How to drive these in class

Step, do not play.Autoplay is there for a second pass. The first time through, use → and ask the class to predict the next step before you press it.
Change the tree.Type a level-order string into the box on any page — e.g. 1 2 3 # 4 5 # 6 7 # # 8. Traversal answers memorised from a perfect tree fall apart on an irregular one, which is the point.
Use the skewed preset.On every page. It is where the complexity discussion becomes concrete instead of theoretical.
Go backwards.← re-runs a step in reverse, which is how you answer “wait, why did it do that?” without restarting.

H is the height: about log N when the tree is balanced, N when it is skewed. W is the widest level. N is the number of nodes, and a tree with N nodes always has N − 1 edges.
