The one observation the whole method rests on

Recursion and an explicit stack both exist for a single reason: a node has no way to get back to its parent. Morris fixes that directly. Before descending into a left subtree, find the node that will be visited last inside it — the inorder predecessor, i.e. the rightmost node of the left subtree — and point its unused right pointer back at the current node. Now the way up exists, inside the tree, for free.
Why the rightmost node always has a spare pointer. If it had a right child it would not be the rightmost. So its right is guaranteed NULL — the one pointer in the whole subtree we can safely borrow.
Threads are the memory. Every node with a left child is reached exactly twice. First arrival: the predecessor's right pointer is NULL → “left subtree not started”, so build the thread and go left. Second arrival: it points back at us → “left subtree finished”, so tear the thread down and output. The presence or absence of that one pointer is the entire state the stack used to hold.

Inorder versus preorder: exactly one line moves

Inorderoutput on the second arrival — after the left subtree
Preorderoutput on the first arrival — before going left
This is the same “first touch versus second touch” idea as the pencil walk on page 5, only now implemented literally: the thread is what tells the two touches apart. Switch modes above and watch which branch the push_back line sits in.
Honest drawbacks. While the traversal is running the structure contains cycles, so it is not a valid tree; the tree must be writable; it is not safe to share with another thread; and the constant factor is worse than plain recursion because some edges are walked three times. Morris postorder also exists but needs reversing the right spine and is rarely asked. Use Morris when the interviewer says O(1) extra space — not by default.

Step

Pointers

That is the complete state of the algorithm: two pointers. Nothing here grows with N — which is what “O(1) extra space” means.

Live threads

At most one thread exists per level of the current left spine, and each is removed as soon as it has been used. When the traversal ends this list must be empty; if it is not, the tree has been corrupted.

Complexity

      
TimeO(N)
SpaceO(1) auxiliary
Space O(1) — genuinely constant: curr and pred. The threads live inside pointers the tree already owns, and the output vector is the answer, not working space. Compare with O(H) for both recursion and the explicit-stack version.
Time O(N) — surprising, because of the inner search for pred. The argument: every edge of the tree is walked at most three times — once while finding a predecessor the first time, once while finding it the second time, and once while moving normally. A tree has N − 1 edges, so the total is under about 3N steps. Same asymptotic class as recursion, larger constant.
